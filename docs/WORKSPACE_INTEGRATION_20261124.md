## 1. 직접 확인한 기존 상태와 문제

`README`, `ARCHITECTURE`, `STATUS`, `TESTING`, 교육과정·수업 관련 문서, App Router/서버 액션/데이터 조회, 연간 계획·교육과정·수업·시간표 엔진, legacy Workspace, SQL 마이그레이션과 테스트를 대조했다. 운영 Vercel 배포 메타데이터는 `main`의 `19d85086c6840295fd85f72be2f95de871a769fe`, READY로 확인했다. 운영 DB의 교원 자료를 조회하거나 변경하지 않았다. DB 구조는 저장소의 SQL을 기준으로 분석하고 새 기능은 격리 PostgreSQL에서 검증했다.

## 2. 명시되지 않았지만 독립적으로 발견·개선한 사항

1. **평균 수업 시수와 실제 배정을 분리했다.** 교육과정의 주당 입력 × 학급 수는 필요한 수업량이다. 시간표에 실제 배정된 수업 수를 별도 열로 표시해 평균을 실제 교사별 배정으로 오해하지 않게 했다. 12학급 × 국어 4시간 = 48시간, 국어 교원 3명 = 평균 16시간을 검사했다.
2. **부족한 자료에서 숫자를 만들어 내지 않는다.** 학기 총시수만 있는 과거 자료를 일괄 16주로 나누거나 고교 학점을 주당 수업 횟수로 간주하지 않는다. 미정 항목이 있으면 평균·부족량·필요 인원의 확정 계산을 보류한다. 선택과목은 전체 학급 개설 가정임을 알린다.
3. **복수 자격에 따른 교원 중복 집계를 막았다.** 여러 과목을 지도할 수 있어도 인원·가용 시수는 주 담당 과목에 한 번만 반영한다. 휴직·전출·퇴직 교원은 가용 인원에서 제외하고, 남아 있는 수업 배정은 검토 대상으로 알린다.
4. **계정 ID와 명부 ID의 중복 교사를 처리했다.** 예전 시간표의 계정 기반 교사 ID와 새 명부 ID가 같은 사람인데 서로 다른 교사로 취급될 수 있었다. 승인된 계정 연결을 기준으로 편집 문서의 모든 `teacherId`를 함께 정규화하고, DB 확정 검사에서도 같은 교사로 비교한다. 저장된 과거 확정본은 바꾸지 않는다.
5. **확정 검사를 서버와 DB에서 수행한다.** 클라이언트만 검증하면 직접 RPC로 잘못된 시간표를 배포할 수 있다. 미지정 교사·과목·학급, 반복 시간표와 날짜별 대체 수업의 학급/교사/특별실 중복, 겹치는 일과 시각, 누락된 요일·교시, 비재직 교원 배정을 거절한다. 저장과 같은 잠금을 사용하고 검토한 버전이 바뀌면 확정을 막는다.
6. **미래 알림을 예약해 놓고 방치하지 않는다.** 열린 앱에서 최신 확정 시간표와 학사일정을 재평가한다. 변경·휴업으로 제외된 수업은 다음 수업 안내에서 빠진다. 홈 밖에서도 안내가 동작하도록 앱 공통 영역에 배치했다. 백그라운드 푸시가 구현된 것처럼 표시하지 않는다.
7. **일요일 업무와 초등 고학년 누락을 수정했다.** 주간계획은 7일을 표시하고, 시간표의 교육과정 연결 개요는 실제 학교의 학년 목록을 사용한다.
8. **시간표 통신 예외에서 편집 내용을 보존한다.** 로드·저장·재조회가 예외로 종료되어도 상태를 해제하고 재시도 안내를 제공한다.

## 3. 요청을 근거로 구현한 기능

### 공통 교원 명부

- 학년도별 이름/임시 이름, 지도 가능 과목, 주 담당 과목, 부서·업무, 담임, 근무 형태, 재직 상태, 목표·경감 시수를 관리한다.
- 교원 등록과 계정 생성을 분리한다. 학교에 이미 가입한 계정의 연결·변경은 관리자만 할 수 있다. 교원 등록으로 접근 권한을 자동 부여하지 않는다.
- 이전 학년도 명부에서 한 교원을 선택해 새 등록안을 만들 수 있다. 원래 기록은 유지하며 담임은 다시 지정한다. 과거 근무 상태·담당 과목은 검토 후 저장한다.
- 관리자/편집자는 수급 자료를, 일반 구성원은 공개 운영 명부와 본인 자료만 조회한다. 명부 조회 RPC는 근무 형태·재직 상태의 상세값·목표·경감 수치를 제외한다.

### 수급 분석·가상 편성

- 운영 학년도의 각 학년에 해당하는 입학년도(`운영 연도 - 학년 + 1`)의 자료를 연결한다. 전체 등록 교과를 계산하며 국어로 한정하지 않는다.
- 학기별 총 수요, 배치 인원, 평균, 경감 반영 가용 시수, 초과/여유, 학교 목표 기준 필요 인원, 실제 시간표 배정을 표시한다. 교육청 정원이나 법정 배치 판정이 아니다.
- 가상 학급 수·주당 시수·교원 수·가용 시수를 바꾸고 결과를 즉시 비교한다. 저장 시 서버에서 공식 자료를 다시 읽어 결과를 계산하고, 입력·계산 결과·교육과정 버전을 별도 스냅샷으로 보존한다. 원본을 바꾸거나 가상안을 자동 승격하지 않는다.
- 저장안 비교·다시 검토·원본 기준 초기화·분석표 인쇄를 제공한다. 과거 저장안의 계산 결과는 현재 원본 변경으로 다시 쓰지 않는다.

### 개인 시간표·확정·알림

- 시간표의 `학교에 저장`과 `검토 후 확정·배포`를 구분했다. 배포마다 읽기 전용 스냅샷을 남기고 개인 홈은 최신 배포본을 사용한다.
- 한국 시각 기준 오늘/이번 주 수업, 현재·다음 수업, 시작까지 남은 분, 교환·보결·취소 안내와 공통 학교/부서 업무를 표시한다.
- 동일 배포 버전의 알림함 항목을 중복 생성하지 않는다. 본인 알림만 조회·읽음 처리한다. 현재 배포 알림은 학교 구성원 전체에 전달된다.
- 브라우저별 0/1/3/5/10/15분 전 설정, 명시적 브라우저 알림 허용, 내부 안내를 제공한다. 열린 앱에서 동작하며 서버 푸시·앱 종료 후 알림은 미구현이다.

### 학사·업무·수업계획 연계

- 날짜/행사 편집 중 저장 전 수업일수 증감과 영향받는 확정 수업을 표시한다. 시간표가 없으면 교과별 손실을 확정할 수 없다고 안내한다.
- 월중·주간·개인 업무는 기존 학사 행사와 연간 계획의 업무를 함께 조회한다. 부서 필터와 7일 주간계획을 추가했다. 미저장 편집이 없는 열린 화면은 30초 간격/복귀 시 갱신한다.
- 실제 편성 시수가 있는 학년·학기·과목으로 수업계획 작성 대상을 구성하고, 연결된 담당자·학급을 새 계획의 초안에 제안한다. 기존 계획은 중복 생성하지 않는다. 교사가 확인한 뒤 저장한다.
- 확정 시간표와 최신 학사일정으로 학급별·주차별 수업 가능 차시와 변경·결손 검토 차시를 표시한다. 학년 운영 교시, 학급별 행사 예외, 반복 활동, 휴업, 교환·보결을 반영한다. 교사가 작성한 내용·평가 비율·기존 확정 문서는 자동으로 덮어쓰지 않는다.

## 5. 검증 근거

최종 로컬 검사: TypeScript·ESLint·프로덕션 빌드 통과, Vitest 211개(이번 작업의 새 테스트 21개 포함)·시간표 Node 테스트 36개 통과, 기존 Workspace 전체 174개 통과. 36개는 Workspace 전체와 범위가 겹치므로 독립 테스트 421개라고 합산하지 않는다. 실습 브라우저 13개(기존 교육과정 8개+통합 5개)도 통과했다. 이후 추가한 확정 검증·초등 연결 변경은 최종 단위/DB/전체 Workspace 검사에 포함했다. 원격 브라우저 결과와 배포 링크는 아래에 별도로 기록한다.

실습 자료는 12학급·19명 교원·3개 입학년도·다수 교과, 국어 48개 주간 수업과 6교시 일과표, 학사 행사와 기존 수업계획을 포함한다.

- PostgreSQL 테스트는 PGlite에서 실제 foundation·시간표·새 migration을 실행한다. Auth 서비스 bootstrap만 가상 구성하고, 익스텐션 선언 중 테스트에서 사용하지 않는 pgcrypto 선언을 제외한다. RLS·RPC·FK·버전·스냅샷은 실제 SQL로 검증한다.
- 명부의 가입 전 등록→계정 연결 시 ID 유지, 변경 이력, 낡은/null 버전 거절, 타 학교 과목/접근 거절, 일반 교원의 수정 거절, 공개 명부의 민감 수치 제외를 검사한다.
- 같은 시간표 버전의 반복 배포, 최신 버전 변경 후 이전 버전 확정 거절, 과거 배포본 불변, 본인 알림만 조회, 알림 내용 위조 거절, 가상안 수정 불가를 검사한다.
- 실제 DB RPC로 중복 배정·누락된 요일·날짜별 보결 충돌·일과 시각 중복·계정/명부 별칭 충돌을 거절하는지 확인한다. 정상 날짜 대체 수업은 허용한다.
- 브라우저에서는 실제 입력·저장·새로고침·다른 모듈 조회·390px 화면까지 확인한다. 실습 UI는 실제 기능 컴포넌트를 재사용하지만 서버 액션을 로컬 실습 저장소로 교체했다. 운영 알림 발송/운영 데이터 수정은 없다.

## 6. 미완료 범위·남은 위험

- **운영/호스팅 DB 통합 인수검증:** 격리 Supabase 인증 계정이 없어 실제 Auth→PostgREST→UI 전 구간은 실행하지 않았다. PGlite 테스트는 다중 프로세스의 실제 경합·운영 환경 설정까지 증명하지 않는다.
- **개인 일정과 세분화된 대상:** 현재 학교 행사·부서 업무는 학교 공유 자료다. 개인 비공개 일정, 대상 교원별 일정 권한·담당자 승인, 구성원별 독립 수정 정책은 추가 설계가 필요하다. 부서 필터는 보안 경계가 아니다.
- **알림:** 현재 시간표 배포 알림은 전체 학교 구성원의 내부 알림함에 생성한다. 영향받은 교원만 선별하거나 행사·업무 변경까지 발송하는 서버 알림, 웹 푸시/PWA/이메일은 미구현이다. 열린 화면도 미저장 편집 중에는 자료 자동 갱신을 보류한다.
- **시간표 구조:** 기존 단일 반복 주간표를 유지한다. 학기별로 완전히 다른 시간표 버전의 적용 기간, 부분 학생 분반, 팀티칭·한 교사의 여러 교과 가용량 분배를 정교하게 다루지 않는다. 합반은 연결 학급 중 하나라도 막히면 전체 수업을 보수적으로 검토 대상으로 표시한다.
- **수급의 법적 판정:** 목표 주당 시수는 학교 계획값이다. 교육청 정원·학교 유형별 배치 기준 자동 판정은 없다. 고교 학점·과거 총시수만 있는 자료는 주당 횟수를 별도로 검토해야 한다. 선택과목의 실제 분반 수는 전체 학급 수와 다를 수 있다.
- **가상안의 공식 반영:** 저장·비교·재검토는 구현했으나 가상안에서 과목 자체를 신설하거나 선택한 안을 공식 교육과정/학급/교원으로 일괄 승격하지 않는다. 담당자가 원본을 직접 검토·반영해야 한다.
- **보존과 삭제:** 명부가 참조하는 주 담당 과목/담임 학급은 FK로 보호된다. 삭제·학급 수 축소 전 연결을 검토해야 한다. 계정 제거 또는 연결 변경에 따른 과거 시간표 귀속 변경은 운영 정책 검토가 필요하다. 시나리오·배포본 목록 UI는 최근 자료 중심이다.
- **작성 대상 자동화:** 실제 과목별 초안을 제안하되 교사 확인 후 생성한다. 학교 전체 계획 일괄 생성·담당 교원 일괄 지정·자동 승인/제출은 추가하지 않았다. 기존 작성·확정 내용은 보호한다.
- **법정 기준/공식 자료:** 이번 통합 작업에서는 새로운 법정 판정 규칙을 도입하지 않았다. 기존 자료의 최신성과 지역별 모든 예외까지 새로 인증한 것으로 볼 수 없다.

## 7. 안전한 운영 반영 절차

운영 배포·운영 데이터 변경에 대한 승인이 없는 상태이므로 여기까지는 코드/격리 검증/Preview만 수행한다.

1. 별도 테스트 Supabase에 기존 모든 migration과 앞선 교육과정 수정, 이번 migration을 순서대로 적용한다. 실제 Auth 계정 3역할로 위 8개 시나리오의 남은 구간을 실행한다.
2. 운영 반영 승인 후, 기존 교육과정·연간 계획·시간표·수업계획의 DB 백업과 내보내기를 준비하고 복원 가능성을 확인한다. 이번 작업에서 운영 백업·복원까지 수행했다고 주장하지 않는다.
3. 추가형 SQL을 먼저 적용하고 권한/RPC를 확인한 뒤 앱을 배포한다. 새 앱은 새 테이블·RPC를 읽으므로 SQL 없이 배포하면 학교 자료 조회가 실패한다.
4. 기존 문서/확정본을 일괄 재계산하지 않는다. 기존 가입 구성원을 교원 명부에 자동 생성하거나 임의 연결하지 않는다. 관리자가 연도별 명부와 계정 연결을 검토한다.
5. 문제가 생기면 이전 앱 배포로 되돌리고 추가 테이블은 보존한다. 새 테이블 삭제로 롤백하지 않는다. 기존 저장 함수 서명과 시간표 JSON 필드를 보존했으므로 이전 앱의 자료를 유지할 수 있다.
