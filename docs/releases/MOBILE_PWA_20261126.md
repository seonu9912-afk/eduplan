## 반영 대상 및 현재 상태

- 사용자 요청: 새 Preview 대신 `https://eduplan-silk.vercel.app`에 반영.
- 개발 브랜치: `codex/mobile-pwa-20261125`. 이 브랜치의 자동 Preview 생성은 비활성화.
- 공식 사이트: GitHub `main` → Vercel Production, Supabase `sssyjkwcsyeyfkqmdgnb`.
- **사이트와 공식 DB는 아직 변경되지 않았다.** 첫 DB 마이그레이션은 자동 승인 검토가 실행 전에 거부했다. 원래 사이트 덮어쓰기 지시와 별도로 운영 DB의 저장 함수 교체·구조 변경에 대한 명시적 승인이 필요하다는 사유였다.
- 검증 DB에는 이전 작업에서 `mobile_push_devices`까지만 적용되었다. 이후 변경을 원래 프로젝트에 적용하기 위한 코드를 준비했다. 검증 DB 자료나 비밀 키를 원래 DB로 복제하지 않는다.

## 구현

- 휴대폰 하단 탐색(홈·일정·시간표·알림·전체 메뉴), 전체 기능 접근, 큰 화면 사이드바, 안전 영역·화면 키보드 대응, 터치 입력과 전체 화면 대화상자.
- 교육과정: 학년·학기·교과군별 과목 카드 편집, 기존 계산·편집권·자동 저장·확정 구조와 전체 편성표 유지.
- 시간표: 수업 선택 후 학급·교과·교원·요일·교시·특별실 변경, 추가·삭제, 날짜별 보결·취소·예외 해제, 두 날짜 수업 교환. 기존 공통 엔진과 버전 저장 사용. 자동편성·전체 편집 화면도 접근 가능.
- 학사일정: 월·7일·일일 목록, 날짜 직접 선택, 수업일·휴업·대체 요일 및 행사 편집 연결. 월중·주간계획은 모바일 날짜별 목록으로 표시.
- 수급: 기존 공통 분석 결과를 교과별 카드로 제공. 교원·학교 설정·권한·교육활동 요청은 공통 반응형 입력 및 기존 저장 경로 이용.
- 교수학습: 주차 선택 후 모든 작성 항목·성취기준·평가 연결 편집. 4시간 한도의 IndexedDB 복구 초안, 서버 버전 비교, 명시적 복원. 서버와 버전이 다르면 자동 덮어쓰지 않고 비교·복사 제공. 복원한 확정 상태는 작성 중으로 전환.
- Manifest, 일반·Maskable·Apple 아이콘, 설치 안내, 기존 수업 알림 Worker를 단일 PWA Worker로 확장. 정적 오프라인 안내와 아이콘만 캐시하며 인증·학교 API와 HTML은 저장하지 않음.
- 업데이트는 사용자 선택으로 적용. 미저장 입력과 저장 중에는 업데이트 차단. 알림 클릭으로 편집 중인 화면을 강제 이동시키지 않음.
- 재접속·앱 복귀·주기적 원본 갱신. 편집 중에는 입력 유지. 기능별 동적 코드 로딩, 홈에서 시수 원본·미확정 시간표·교원 가상안 등 불필요한 조회 축소.
- 푸시: 기기별 이름·알림 시간·상세 표시·변경 알림 설정. 잠금 화면 상세 정보 기본 숨김. 로그아웃은 해당 기기 구독 해제 및 로컬 초안·표시 알림 정리. 이전 계정 연결은 브라우저 구독 키 소유 확인 후 해제.
- 확정 시간표 및 교육활동 요청·처리 결과를 기존 알림함과 서버 푸시에 연결. 발송 직전과 수신 직후 권한·원본 상태 재검증. 수업 알림과 변경 알림의 중복 방지 기록 분리. 로그인 후 관련 화면 복귀.

## 승인 요청 대상

다음 20건을 순서대로 원래 Supabase 프로젝트에 적용한다. 앞선 통합 계획 개발의 DB 구조도 포함되며, 모바일 화면만 단독 배포하면 필요한 RPC가 없어 저장·조회에 실패한다.

- 공통 교원 명부·배치, 날짜별 학사 운영, 시간표 참조·배정, 시정표·확정 버전 구조 추가.
- 교육과정 입력·조정 시수의 관계형 투영, 교수학습 공통 참조, 활동 요청·승인과 수업 실시 기록 추가.
- 저장·확정 함수 교체, 동시 편집 및 학교·역할별 검사 유지·강화.
- 알림 구독·기기 설정·원본 연결·전달 기록 및 제한된 RPC 추가.
- 원본 문서와 기존 테이블을 삭제하지 않음. 학사일정 원본 보관 및 새 테이블로 투영. 교원·과목의 이름만으로 기존 자료를 합치지 않음.

## 적용 절차와 복구 범위

1. 명시적인 운영 DB 변경 승인 확인.
2. 현재 스키마·마이그레이션 목록 재확인 후 누락분만 순차 적용. 실패하면 다음 단계와 프런트 배포 중지.
3. 사전에 계산한 학사일정·시간표·교육과정 문서·시수·행사·교수학습 과정 원본 해시와 적용 후 값을 비교. 최초 조사: 시수 240건, 학사 문서 2건, 시간표 1건, 편성 문서 2건, 행사 54건, 과정 1건. 교육과정 셀 중복 및 학사일정 범위 이탈 없음.
4. Production 전용 푸시 런타임 구성, 권한 검사 및 서버 상태 확인. 비밀 키는 로그·Git에 기록하지 않음.
5. `main` 최신 상태 확인 후 fast-forward 반영하고 Vercel Production 빌드·공식 주소 연결 확인. 강제 push 및 임의 환경 전환 금지.
6. 코드 문제는 이전 Vercel 배포로 복귀 가능. DB는 자동 하향 마이그레이션하지 않으며 추가한 구조·이력을 보존한 상태에서 원인별 복구한다. 저장 함수가 교체되므로 단순 파일 배포와 동일한 위험 수준은 아니다.

## 확인 범위와 남은 사항

- 타입 검사, 린트, 기존 211개 Vitest + 36개 legacy 테스트 통과. Next 배포 빌드 성공. 별도 사용자 시나리오·가상 학교·인수 테스트는 수행하지 않음.
- 전체 SQL 마이그레이션의 로컬 DDL 컴파일 확인. Supabase 인증·확장 기능은 로컬 스텁이므로 실환경 RLS 검증을 대체하지 않음.
- 휴대폰·태블릿 실기기 사용성, 설치 및 실제 푸시 수신은 미확인. iOS/iPadOS Web Push는 홈 화면 설치 및 지원 버전(16.4+) 필요. OS·브라우저 정책에 따라 도착 시각이 달라질 수 있음.
- 학교 행사·대체 요일·시정표 변경 각각에 대한 별도 서버 푸시 발송은 아직 연결되지 않음. 실제 수업 산출과 다음 수업 알림은 변경된 공통 운영 원본을 참조함.
- 완전 오프라인 편집·승인·확정, 네이티브 앱 및 앱스토어 등록은 포함하지 않음. 오프라인에서는 안전한 안내와 이미 열린 입력 보존·교수학습 초안 복구만 지원.
- 운영 배포 및 새 푸시 서버 실제 활성화는 DB 변경 승인 전까지 보류.
