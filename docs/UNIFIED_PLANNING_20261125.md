# 통합 계획 원본 전환 — 2026-11-25

개발 브랜치: `codex/unified-planning-20261125`. 운영 DB와 운영 사이트는 변경하지 않았다.

## 이번 구현

- 교원에게 학교 공통 식별자를 부여하고 학년도 배치와 분리했다. 이전 명부에서 새 학년도 등록안을 만들 때 식별자를 유지하며, 이름이나 회원가입 정보로 자동 병합하지 않는다.
- 시간표의 수업 배정, 주간 수업, 날짜별 변경, 활동반·학급 연결을 관계형으로 저장한다. 과목·교원·학급·특별실에 학교/학년도 외래 키를 적용했다.
- 이전 시간표의 독립 ID는 담당자가 공통 목록에서 연결한다. 원본 저장본과 연결 이력을 보존한다. 연결되지 않은 사용 중인 참조는 저장을 중단한다.
- 학사일정의 날짜별 운영과 학년별 교시 예외를 관계형으로 분리했다. 기존 학사일정 저장 트랜잭션이 관계형 원본과 호환 문서를 함께 갱신하고, 화면은 관계형 날짜 자료를 읽는다. 읽는 중 원본 버전이 바뀌면 오류를 표시한다.
- 특별 시정표를 재사용 가능한 불변 교시 자료로 저장하고 기간별로 적용한다. 수업 종료와 귀가 목표, 최소 수업·쉬는 시간, 점심·종례를 계산하며 두 가지 우선순위의 편성안을 제공한다. 적용 기간 중복은 DB에서 차단하고 적용 해제 이력을 남긴다.
- 확정 시간표에 적용 시작일을 지정한다. 과거 확정본을 덮어쓰지 않고 날짜에 맞는 버전을 선택한다. 기본 시간표 요일과 특별 시정표를 각각 결합한다.
- 홈·교수학습계획·시간표 날짜별 조회·예상 시수 및 CSV가 공통 계산을 사용한다. 상충하는 날짜 변경과 교원/학급/특별실 충돌은 정상 수업으로 처리하지 않는다.
- 다른 메뉴 편집 중에도 수업 알림 직전에 서버의 확정 자료를 다시 읽는다. 조회 실패 시 알림을 보류한다. 브라우저가 닫힌 상태의 웹 푸시는 아직 지원하지 않는다.
- 두 교육과정 공개 SECURITY DEFINER 구현을 private으로 이동하고 공개 함수는 invoker로 유지했다. 내부 소속·권한 검사는 보존했다.

## 데이터 전환과 남은 경계

`eduplan-acceptance` (`qvohqvwhjkgvgzbzyzrr`)에 이전 개발분 2개와 이번 마이그레이션 4개를 적용했다. 운영 데이터를 검증 환경으로 복사하지 않았다. 기존 학사일정 5건과 버전의 원본 보존 및 날짜 행 3건의 일치를 조회로 확인했다. 공개 테이블 RLS와 공개 SECURITY DEFINER 경고 해소를 확인했다.

마이그레이션 순서는 파일명 순서이며, 이전 두 개는 `curriculum_consistent_term_hours`, `workspace_operations`이다. 이번 네 개는 `unified_planning_sources`, `normalized_timetable_operations`, `dated_bell_schedules`, `effective_timetable_publications`이다. 원격 이력의 생성 시각은 로컬 파일 시각과 다르므로 운영 반영 시 이름과 스키마를 함께 비교해야 한다. 기존 테이블을 삭제하지 않았다.

아직 전체 지시서의 완료 상태는 아니다. 교육활동 추천·승인, 실제 실시/인정 시수 원장, 업무별 세분 권한, 관계형 교육과정 주당 입력의 완전 전환, 교수학습계획 담당 교원 연결의 완전 전환, 서버 푸시 알림은 후속 구현이 필요하다. 기본 시정표 편집 설정과 일부 학사일정 설정·일반 업무 일정은 기존 JSON 구조를 사용한다. 기존 교육과정 Excel/운영표는 이력과 호환성을 위해 유지된다.

회원 계정과 교원 연결은 관리자가 승인하며, 기존 운영 시간표의 미연결 과목·교원은 실제 담당자의 명시적 매핑이 필요하다. 기존 확정 시간표에 적용 시작일이 없는 경우 운영 화면에서 미설정으로 표시한다.

요청에 따라 별도 인수 테스트나 전체 화면 수동 검증은 수행하지 않았다. 기본 타입·린트·빌드와 저장소 배포 명령에 포함된 기존 자동 검사만 사용하며, 이를 사용자 업무 흐름 검증 완료로 간주하지 않는다.

유출 비밀번호 보호는 [Supabase Pro 이상 기능](https://supabase.com/docs/guides/auth/password-security#password-strength-and-leaked-password-protection)이다. 요금제 및 인증 정책 변경은 수행하지 않았다. 운영 반영은 별도 승인, 백업/복구 준비, 기존 자료 매핑 검토 후 진행해야 한다.
