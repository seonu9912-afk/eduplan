# 기존 학사일정 프로그램 검토

2026-11-08. 제공받은 Google Apps Script 백엔드(v13.9.0)와 HTML 화면을 검토했습니다. 원본 프로그램을 실제 배포·실행한 검증은 아니며, 아래 계산 불일치는 원본의 해당 순수 함수를 분리해 재현했습니다. 원본에 포함될 수 있는 인증 정보는 이 저장소에 복사하지 않았습니다.

## 유지할 기능

| 기존 기능                               | EduPlan에서의 반영 방향                                                  |
| --------------------------------------- | ------------------------------------------------------------------------ |
| 학년도 초기 설정·전환·보관              | 작업공간별 학년도·학기와 연결하고 변경 이력 보존                         |
| 수업일·휴일·방학·재량휴업일·대체수업일  | 날짜별 종류, 사용 여부, 실제 수업 요일, 시작·종료 교시를 명시적으로 관리 |
| 요일별 시간표와 반복 창체               | 학년·학기·요일·교시 규칙 및 제외일을 저장                                |
| 행사별 교시와 학년별 활동 구분          | 같은 행사의 대상 학년별 교시 배정으로 확장                               |
| 공휴일 미리보기·충돌 확인               | 공식 데이터 출처와 수동 수정 내역을 구분하고 선택 적용                   |
| 수업일수·시수 점검                      | 화면·검사·내보내기가 같은 계산 결과 사용                                 |
| Excel 양식·행사·학사일정·주별 시수 출력 | 계산과 파일 생성을 분리하고 가져오기 전 검증 제공                        |
| Google Calendar 동기화                  | 앱이 만든 일정만 식별해 갱신하는 원칙 유지                               |
| 스냅샷·복원·수정 충돌 확인              | DB 트랜잭션, 버전 비교, 변경 이력에 통합                                 |

원본의 ‘주별 수업일수·시수 보고서’는 추후 별도로 제공될 월중계획·주간계획 프로그램과 구분합니다. 해당 두 프로그램은 아직 검토하지 않았습니다.

## 확인한 개선점

1. **화면과 내보내기의 사용일 판단이 다릅니다.** 사용=false인 수업일 하나에 6교시를 배정하면 화면의 `actualHours`는 6시간을 계산하지만 서버의 `activeDays_`는 그 날을 제외합니다. 날짜·학년·교시 배정을 하나의 계산 함수로 모아 이 불일치를 없애야 합니다.
2. **학기 기준이 간접적입니다.** `semesterForDate_`는 여름방학 종료일 또는 월로 학기를 추정합니다. EduPlan에 저장한 실제 학기 시작·종료일을 공통 기준으로 사용해야 합니다.
3. **중복 교시와 부족 시수를 명확히 드러내야 합니다.** 중복 배정 경고와 별개로 합산 경로에서 이중 계산될 여지가 있고, 음수를 0으로 제한하면 원인을 놓칠 수 있습니다. 교시별 충돌과 실제 합계를 따로 보여주는 구조가 필요합니다.
4. **학사일 재생성에서 수동 설정을 보존해야 합니다.** `buildAcademicDays_`는 재생성 시 사용 여부를 true로 만들고 방학 구간을 다시 적용합니다. 원본 규칙·공식 공휴일·사용자 수정값을 구분하고 재계산 전 변경 내역을 보여줘야 합니다.
5. **3학년 고정을 제거해야 합니다.** 원본에는 학년 1~3 반복이 많습니다. 이번 EduPlan 변경에서 학교급과 학년 범위를 공통화했으며 향후 학사일·교시 계산도 같은 기준을 사용합니다.
6. **인증·저장 방식은 현재 웹서비스에 맞춰 이관해야 합니다.** 공유 관리자 비밀번호와 시트 전체 덮어쓰기를 옮기지 않고, 기존 Supabase 계정·구성원 권한·RLS·트랜잭션을 사용합니다. 외부 API는 서버에서 호출하며 오류에 인증키가 포함되지 않도록 처리해야 합니다.

## 이관 순서

1. 날짜별 학사 운영: 수업일 종류, 사용 여부, 방학·휴업·대체 요일, 수동 수정 내역.
2. 학년별 요일 시간표와 행사 교시 배정, 반복 창체 및 예외 날짜.
3. 날짜 × 학년 × 교시의 공통 계산과 충돌 검사. 수업일수·교과·창체 시수의 화면/출력 일치 검증.
4. 공휴일·나이스 자료 미리보기, 선택 반영, Excel 입출력, 캘린더 연동.
5. 별도 월중·주간계획 프로그램을 검토한 뒤 같은 행사 원본에 연결.

학교별 자료는 workspace_id·academic_year_id로 격리하고 RLS를 적용합니다. 법정 기준과 창체 분류는 확인한 교육과정 버전·출처에 따라 모델링하며, 기존 프로그램의 분류를 모든 학교급에 그대로 적용하지 않습니다.

## 이번 반영과 남은 범위

- 반영: 첫 화면의 실제 로그인 통합, 별도 회원가입 화면 유지, 초·중·고 선택, 초등 1~6학년/중·고 1~3학년 설정·일정·교육과정, 학교급 축소 시 기존 자료 보호.
- 준비: 나이스·공휴일 인증키를 서버 전용 환경변수로 저장. 나이스 학교정보 API의 정상 응답 확인.
- 후속 이관: 연간 12개월 기본안, 방학·휴업·사용 여부·수업 요일 교체·날짜별 교시, 학년별 기본 교시, 반복 활동·제외일, 행사 교시·학년별 영역, 공통 시수 계산, 변경 이력 30개·복원, JSON 백업과 교시 행사 Excel 가져오기, Excel 보고서를 구현했습니다.
- 남은 범위: Google Calendar OAuth 연결·동기화, 교시 없는 기존 행사 Excel의 직접 가져오기, 기존 Google Sheets 전체 DB의 자동 변환. 교시 없는 행사는 웹의 행사 일정에서 등록할 수 있습니다.
- 월중·주간 업무계획: 학교 행사와 교시 행사를 함께 표시하고 부서별 업무·출장·당직·협의사항은 별도로 저장합니다. 사용자가 추후 제공할 별도 두 프로그램을 검토한 결과는 아닙니다.
- 공휴일·기상청: 개발 환경에서 코드 10을 재현했으나 동일한 키를 사용한 운영 서버에서 정상 응답을 확인했습니다. 공휴일 00·22개 파싱, 기상청 3종 모두 00·실제 예보 표시를 확인했습니다. [상세 진단](PUBLIC_API_DIAGNOSTIC.md).

## 실행 화면 비교 후 개선

사용자가 제공한 Apps Script 실행 URL에 실제 접근하여 학사일정 관리 화면의 전체·학기별 수업일수, 방학 설정, 3월~다음 2월 행렬 달력, 월별 합계, 공휴일 보존 동작을 확인했습니다. 원본 학교의 181일은 해당 학교가 저장한 계획의 결과이며 새 작업공간의 기본값으로 복사하지 않습니다.

EduPlan도 연간 화면 진입 즉시 수업일수를 표시하고, 연간표·월별 달력 전환, 날짜를 누르는 편집창, 방학 구간 수정·삭제, 월별 수업일수, Excel 수업일수 요약을 제공합니다. 공휴일은 버튼 하나에서 두 해를 조회하고 학년도 범위만 반영합니다. 시간표를 입력하지 않은 상태에서도 수업일수는 계산합니다.
