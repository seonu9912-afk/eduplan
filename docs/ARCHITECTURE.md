# 데이터 및 배포 설계

## Phase 0 확인 (2026-11-07, Asia/Seoul)

- 공식 저장소 `seonu9912-afk/eduplan`: 빈 저장소. 메타데이터상 쓰기·관리 권한이 있으나 실제 업로드와 설정 변경은 연결 토큰의 HTTP 403으로 실패.
- Public → Private 변경은 사용자가 승인했으나 연결 토큰에서 HTTP 403 반환. 설정 변경 미완료.
- 기존 Supabase 비활성 프로젝트와 기존 Vercel 타 프로젝트는 수정하지 않음.
- 승인받은 조직에 전용 Supabase `eduplan` 프로젝트 생성, 서울 리전, 초기 public 테이블 없음.

## 원본 데이터와 관계

`auth.users → profiles → workspaces ↔ workspace_members`

학교는 school 타입 작업공간의 부가 정보이며 `schools.id = workspaces.id`이다. 개인·학교 작업공간은 동일한 편집 기능을 쓰되 서로 다른 workspace_id와 RLS 경계를 가진다. 학교 소속 레코드는 school_id도 기록한다.

`workspaces.school_type`이 개인·학교 공간의 학년 범위를 결정한다. 초등학교 1~6학년, 중·고등학교 1~3학년이며, 학교의 부가 정보에도 같은 학교급을 기록한다. 기존 공간의 기본값은 중학교이다. `set_school_type` RPC는 관리자만 실행하며 4~6학년 학급·시수·대상 일정이 있으면 중·고등학교 변경을 거절한다. 학년 관련 쓰기 트리거는 현재 구성원 권한을 확인한 뒤 작업공간을 잠가 학교급 변경과 동시에 범위를 벗어난 자료가 저장되지 않게 한다.

`workspaces → academic_years → semesters / classes / events`

연간·월간·주간 출력은 events 한 테이블을 조회한다. 날짜는 DATE, 기록 시각은 timestamptz를 사용하고 UI 날짜 기준은 Asia/Seoul이다. 학생 개인정보를 수집하지 않는다.

`workspaces → subject_groups → subjects`

`workspaces → curriculum_plans(cohort_year) → curriculum_hours(subject,grade,semester,hours)`

운영 학년도 Y의 학년 G는 입학년도 Y-G+1의 편성표를 참조한다. 학생 교육과정 시수와 향후 개설 수업·교사 담당 시수는 별도 엔터티로 확장한다. 법정 시수는 확인된 교육과정 기준 버전과 출처를 별도 모델로 추가하기 전까지 고정값을 쓰지 않는다.

## 로그인 진입점

`/`에 소개와 로그인 폼을 함께 제공한다. `/login`은 기존 링크를 위해 `/`로 이동하며 허용된 내부 `next` 경로를 보존한다. 로그인한 사용자는 `/app` 또는 유효한 반환 경로로 이동한다. 회원가입·비밀번호 재설정은 별도 화면이다. 첫 화면도 세션 갱신과 private/no-store 처리를 적용한다.

## 권한

- admin: 학교 설정·학년도·초대·구성원·편집
- editor: 일정·교육과정 편집, 학교 설정 및 권한 변경 불가
- viewer: 조회 전용
- 개인 작업공간은 소유자만 접근
- RLS는 현재 membership를 조회하여 탈퇴·권한 회수 즉시 반영
- 연관 데이터는 workspace_id를 포함한 복합 외래키로 교차 학교 연결 차단
- 초대 토큰은 일회용이며 해시만 저장, 이메일 일치·만료·철회 확인
- 권한 상승 및 원자적 작업에 필요한 함수만 private 스키마의 명시적 SECURITY DEFINER로 구현. 공개 RPC는 invoker 래퍼, PUBLIC/anon 실행권한 취소
- 편성표 전체 저장은 트랜잭션 및 버전 비교로 동시 편집 손실 방지

## 연간 학사일정

`annual_academic_plans`는 학년도당 연간 기본안 1개를 저장합니다. workspace와 academic_year의 복합 외래키, 멤버십 조회 RLS, 편집자/관리자 RPC, 버전 비교로 공간 격리와 동시 편집을 처리합니다. pg_jsonschema 제약으로 API를 직접 호출해도 잘못된 문서 구조를 저장할 수 없습니다. 학교급 변경은 연간 문서의 4~6학년 자료도 검사합니다. 최근 30개 이전 문서를 저장하며 복원 역시 새 버전 저장으로 처리합니다.

학사일·교시 계산은 `src/lib/academic.ts`에서 한 번 수행하며 화면·Excel이 같은 함수를 사용합니다. 수동 날짜 수정 > 공휴일 > 방학 > 요일 기본값 순서이며, 실제 학기 밖과 사용 해제일은 제외합니다. 행사 교시가 반복 활동보다 우선하고 행사 간 또는 반복 규칙 간 중복 교시는 별도 표시해 영역 시수를 이중 합산하지 않습니다.

부서 업무·출장·당직·협의사항은 학사일정의 행사와 구분되는 business 항목입니다. 월중·주간 화면은 학교 공통 행사, 연간 교시 행사, 업무 항목을 함께 표시합니다. 공휴일·기상청은 서버 전용 키와 캐시를 사용하고 오류 원문을 반환할 때 키를 제거합니다. 공휴일 XML의 정상 코드와 전체 데이터 파싱 성공을 모두 확인해야 가져오기를 허용합니다.

수업일수는 시간표 입력 여부와 독립적으로 `isTeachingDay`에서 날짜당 한 번 계산합니다. 사용 중이며 실제 학기 안에 있는 수업일·요일 교체일만 포함합니다. 상단 연간·학기별 요약, 월별 합계, 학년별 집계, Excel 요약은 같은 계산을 사용합니다. 시간표가 없는 수업일은 1일·0시간으로 집계하고 교시 설정 점검을 표시합니다.

공휴일 버튼은 해당 연도와 다음 연도를 서버에서 병렬 조회합니다. 두 응답이 모두 정상·완전 파싱된 경우에만 3월~다음 해 2월을 필터링해 초안에 합칩니다. 하나라도 실패하면 초안을 변경하지 않습니다. 수동 학사일·방학·행사·업무 문서는 변경하지 않으며 일반 연간 저장을 통해 DB에 반영합니다.

과목 삭제는 `delete_subject` RPC에서 작업공간 배타 잠금 → 모든 편성표 버전 확인 → 연결 시수와 과목 삭제 → 편성표 버전 증가·활동 기록을 한 트랜잭션으로 수행합니다. 편성표 저장·생성이 먼저 잡는 작업공간 공유 잠금과 직렬화하여 삭제 중인 과목 시수가 다시 저장되는 것을 막습니다. 관리/편집자만 호출할 수 있고 직접 테이블 삭제 권한은 부여하지 않습니다.

연간 기본안의 이력 복원·가져오기는 기존 부서 업무와 부서 목록을 보존합니다. 업무계획 저장은 같은 문서의 최신 버전을 비교하므로 다른 화면에서 바뀐 학사일정을 덮어쓰지 않습니다.

## 수업·평가 추가 (2026-11)

기존 workspace/year/subject/classes 관계를 재사용한다. 담당 수업, 공통 계획, 학급 연결, 사용자 등록 성취기준, 기준 연결, 버전 이력의 여섯 테이블을 추가했다. 단원·평가·루브릭은 strict JSON Schema로 검증하고 관계형 성취기준 FK를 같은 트랜잭션에서 저장한다.

소유자와 현재 작업공간 멤버십을 함께 검사한다. 비공개 계획은 학교 관리자도 읽을 수 없고, 공유 계획은 소유자와 관리자만 편집한다. 조회 전용 역할의 생성/수정, 타 학교/개인 공간/학년도 연결은 RPC와 RLS/복합 FK에서 차단한다. 서비스 역할 키를 앱에 사용하지 않는다.

계획 버전과 내용을 한 번의 관계 조회로 가져오며 버전 비교 저장(CAS)으로 동시 수정 충돌을 차단한다. UI는 서버 재검증이 오더라도 미저장 내용을 보존한다. 편성/학사 기준은 변경 알림 후 명시적으로 갱신하며 교사 작성 내용을 덮어쓰지 않는다. 자세한 관계·제약·후속 범위는 [TEACHING_MODULE.md](TEACHING_MODULE.md)를 참조한다.
