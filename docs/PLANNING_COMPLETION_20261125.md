# 학교 계획 운영 기능 후속 구현

브랜치: `codex/planning-completion-20261125`. 이전 통합 작업(`338422d`, `acd9edb`)에 이어 교육활동 요청, 수업 기록, 업무 권한, 공통 참조 및 서버 알림을 추가했다. 운영 Supabase와 운영 도메인은 변경하지 않았다.

## 구현한 업무 흐름

- **학사일정 → 교육활동 편성 요청**: 희망 기간, 교시 수, 대상 학급, 필수 교원, 특별실, 고정 조건과 대체 방식을 입력한다. 공통 일일 시간표·행사·확정 평가 일정을 조회하여 후보와 교과 대체 영향, 충돌, 미확인 정보를 제시한다. 요청자는 후보를 선택해 제출하고 학사 담당자는 최신 분석을 다시 확인한 뒤 승인·조정 요청·반려한다. 승인 시 행사와 학급별 교시 배정을 기존 공식 일정에 한 트랜잭션으로 등록한다. 승인된 활동의 현재 날짜는 원본 학사일정에서 읽는다.
- **시간표 → 수업 실시 확인·인정 시수**: 기간·학급·과목별 확정 예정표와 기록을 조회한다. 본인에게 연결된 수업 또는 담당 권한이 있는 수업을 개별·일괄 확인한다. 실시 시간(분), 취소, 인정 시수, 사유를 분리한다. 미래 수업은 확인하지 않으며 수업이 끝나기 전의 확인도 서버 액션에서 차단한다. 인정 시수는 자동 확정하지 않는다. 계획 변경으로 예정표에서 사라진 기록도 보존한다.
- **구성원 → 업무별 편집 권한**: 관리자가 편집 구성원의 교육과정·학사일정·시간표·평가·수급·월중주간계획 권한을 지정한다. 기존 구성원 역할과 기본 권한은 자동 변경하지 않았다. 화면 제어와 DB 쓰기 제한을 연결했다. 일반 구성원의 교육활동 요청과 본인 수업 확인은 별도로 허용한다.
- **교육과정**: 주당 입력 및 조정 내역을 관계형 행으로 투영하고, 화면과 교원 수급 조회가 그 행을 재구성한 동일 자료를 읽도록 변경했다. 기존 편성 문서는 호환 입력·표현 정보이며 별도 수정 원본이 아니다. 같은 트랜잭션에서 기존 자동 시수 계산과 관계형 입력을 갱신한다. 설계 문서가 있는 편성표는 이전 시수 API로 독립 덮어쓰지 못한다.
- **교수학습계획**: 담당 교원을 학년도별 공통 교원 ID로 연결한다. 신규 일반 수업은 공통 과목·교원을 선택하거나 미연결 사유를 남긴다. 기존 미연결 과목은 확정되지 않은 계획에서 연결할 수 있다. 작성 중 표시명은 공통 원본에서 읽고 확정본 표시명과 내용은 유지한다. 이름만 같은 기존 자료를 자동 병합하지 않는다.
- **홈 → 서버 수업 알림**: 브라우저가 지원하면 사용자가 직접 구독·해제하고 알림 시점을 선택한다. 공통 학사 엔진을 Edge Function에 번들하여 발송 직전 최신 수업을 다시 산출한다. 수신 Service Worker도 로그인된 최신 수업을 재확인한다. 예전 시간표 기반 알림을 미래 큐에 독립 저장하지 않는다. 실패·만료된 구독은 정상 전달로 표시하지 않는다.

## 독립적으로 보완한 부분

요청 수정 시 대상 학급·교원 연결을 삭제하지 않고 현재 적용 여부를 갱신하며, 요청 입력 스냅샷을 남긴다. 관계형 교육과정 입력에는 원본 버전을 기록하고 이전 행을 보존하며 현재 버전만 계산에 사용한다. 교원 수급 검토 자료는 일반 공통 명부와 다른 업무 권한으로 조회를 제한한다. 확정 시간표가 없는 수업일은 0시간으로 완전 계산된 것처럼 보여주지 않고 미계산 범위를 안내한다.

## 저장 구조와 적용 범위

검증 프로젝트 `qvohqvwhjkgvgzbzyzrr`에 아래 마이그레이션을 적용했다. 로컬 파일은 Supabase CLI로 생성했으며, 원격 적용 타임스탬프는 다르므로 이름과 내용으로 대응한다.

- `planning_completion`: 업무 권한과 기존 쓰기 경로 보호
- `activity_requests_and_lesson_records`, `activity_request_commands`, `activity_request_approval`, `activity_request_save`: 요청·대상·이력, 분석 버전, 제출·승인
- `lesson_record_ledger`: 실시·인정 기록과 이력
- `curriculum_relational_inputs`: 관계형 주당 입력·조정, 일관된 읽기
- `teaching_common_references`: 공통 교원 연결과 기존 계획 호환
- `server_lesson_push`, `lesson_push_scheduler`, `scoped_push_heartbeat`: 사용자별 구독, 서비스 전용 발송 함수, 정기 실행 기반

기존 테이블과 공식 스냅샷을 제거하지 않았다. 검증 DB의 학사일정 5건과 교수학습계획 5건은 적용 전후 내용 해시가 동일하다. 이 환경에는 교육과정 설계 문서와 시간표 확정본이 없어 해당 데이터의 실제 이전·운영 성공까지 확인한 것은 아니다. 운영 데이터는 검증 환경으로 복사하지 않았다.

## 배포·운영 참고

`npm run build:push`는 공통 학사 로직에서 `supabase/functions/lesson-push/engine.mjs`를 생성한다. 엔진을 수정하면 다시 생성하고 Edge Function과 앱을 함께 배포해야 한다. Edge Function은 `deno.json`을 명시하여 배포한다. JWT 게이트 대신 Vault의 전용 dispatch 비밀값을 서버에서 검사하며, 런타임 비밀 조회·발송 RPC는 service_role만 실행할 수 있다.

검증 환경에만 `lesson-push` 함수와 매분 실행 Cron을 설치했다. VAPID 개인 키·dispatch 비밀값은 Vault에 보관하며 브라우저에는 공개 키만 제공한다. `scripts/prepare-push-runtime.mjs`는 검증 프로젝트만 허용하고 기존 런타임 키를 덮어쓰지 않는다. 설치용 비밀 SQL은 저장소에 포함하지 않는다. 사용자 구독은 자동 생성하지 않는다. 2026-11-25 22:00 UTC 정기 실행에서 HTTP 200, 발송 0건·실패 0건과 정상 heartbeat를 확인했다. 당시 구독자는 0명이므로 실제 기기 전달 검증을 의미하지 않는다.

## 확인 범위와 남은 한계

기존 배포 검사(타입, 린트, Vitest 211건, 기존 시간표 검사 36건)와 빌드, 로컬 마이그레이션 DDL 생성을 확인했다. 로컬 DDL 검사는 JSON schema 확장의 대체 함수로 구문·참조를 확인한 것이며 업무 시나리오 검증이 아니다. 지시대로 별도 가상 학교나 대규모 테스트 데이터, 전체 화면 수동 검사, 인수 테스트는 수행하지 않았다.

등록되지 않은 교내 사정과 날짜가 없는 평가는 자동 확정하지 않는다. 행사별 교과 시수 인정의 법적 판정은 자동화하지 않았다. 기존 미연결 교원·과목은 담당자의 명시적 연결이 필요하다. 알림은 지원 브라우저의 권한·유효한 로그인·연결된 교원·확정 시간표가 필요하다. 실제 기기 수신 여부는 이번 작업에서 확인하지 않았다. 일부 편집 설정과 기존 Excel·운영표 호환 문서는 계속 JSON을 사용하며 물리적 삭제는 하지 않았다.

운영 반영에는 별도의 승인과 운영 DB 백업·마이그레이션 검토가 필요하다. 유출 비밀번호 보호 경고는 기존 계정/요금제 설정에 관한 항목으로 임의 변경하지 않았다.
