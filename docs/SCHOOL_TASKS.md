# 나의 할 일과 업무 배포

## 데이터와 권한

- `school_tasks`에 개인 할 일 또는 배포 업무의 공통 원본을 저장합니다. 배포자는 같은 학교의 해당 학년도 재직 교원으로 계정에 연결되어야 합니다. 업무별 편집 권한이나 학교 관리자 역할과는 별개입니다.
- `school_task_recipients`에 배포 시 확인한 교원·계정과 각 수신자의 완료 시각을 저장합니다. 명부나 부서가 바뀌어도 기존 행을 유지합니다. 계정과 교원 식별자의 연결이 바뀐 경우 같은 업무에서 다른 계정으로 기록을 넘기려는 요청은 거부합니다. 제외된 수신자는 해당 업무의 조회 권한이 해제되고, 배포자의 진행 기록에는 남습니다.
- 두 테이블의 RLS는 학교 소속을 확인한 뒤 개인 할 일의 작성자, 배포 업무의 작성자와 해당 수신자만 허용합니다. 수신자 목록 전체는 배포자만 읽습니다. 쓰기는 권한·버전을 확인하는 트랜잭션으로 실행합니다.
- 배포·수정·마감 변경·제외·취소·재수행 요청은 기존 `operation_notifications`에 저장됩니다. 업무 버전·수신 계정 조합은 고유합니다. 알림 읽음과 완료는 별도 상태입니다. 업무 알림은 앱 알림함에서 제공하며, 푸시와 마감 자동 알림은 연결하지 않았습니다.

## 업무계획 연결 규칙

- 학교·학년도별로 적용 중인 공개 업무계획의 기존 항목 ID를 저장합니다. 한 항목은 같은 학교·학년도에 한 번 배포할 수 있습니다. 취소 이력도 이 고유 조건에 포함됩니다.
- 제목은 적용 중인 공개본을 따라갑니다. **공개 업무계획 날짜를 마감일로 사용**을 선택한 경우에만 마감일도 따라갑니다. 직접 입력한 마감일과 마감 시각은 배포 업무가 관리합니다.
- 공개본에서 항목이 사라지면 마지막 공개 제목·날짜와 기존 수신·완료 기록을 사용합니다. 배포 관리 화면에서 원본 누락을 확인하고 유지하거나 업무를 취소할 수 있습니다. 이름이 같은 새 항목에 자동으로 재연결하지 않습니다.
- 배포 업무를 직접 수정하면 수신자에게 업무 알림을 보냅니다. 업무계획 공개에 따른 제목·날짜 갱신은 적용일에 조회 화면에 반영되며 기존 공개 계획 알림 경로를 사용합니다.

## 검증 및 운영 반영 절차

1. 최신 `main`을 기준으로 검토합니다. 운영 DB의 마이그레이션 이력에 `mobile_operation_notifications`가 있어 `operation_notifications.operation_source`가 존재하는지 확인합니다.
2. 테스트 DB에 `20261127093019_school_tasks.sql`을 적용합니다. `npm run check`, `npm run build`와 격리 환경의 `tests/e2e/school-tasks.spec.ts`를 실행합니다.
3. 승인 후 운영 DB에 마이그레이션을 먼저 적용하고 확인합니다. 이 변경은 새 업무 테이블과 기존 알림의 업무 참조 열을 추가하며 기존 알림 자료를 갱신하지 않습니다.
4. PR을 병합해 운영 빌드를 완료한 뒤 승인된 학교 계정으로 홈, 주간계획, 업무 배포, 알림 링크를 확인합니다. 앱 롤백이 필요하면 이전 빌드로 되돌려도 기존 업무 데이터는 보존됩니다. 해당 빌드에서는 할 일 화면과 업무 알림으로 이동하는 동작이 제공되지 않습니다. 배포 후 축적된 업무 기록이 있는 상태에서 테이블을 삭제하는 역마이그레이션은 사용하지 않습니다.

브라우저 테스트의 `EDUPLAN_TASK_FIXTURES`는 가상 학교의 `workspace`, `year`, `administrator`, `sender`, `recipient`, `second`를 담는 비추적 JSON 파일입니다. 계정에는 각각 `email`과 `password`를 제공하고, 배포자 한 명과 수신자 두 명을 재직 명부에 연결합니다. 수신자 한 명은 1학년 담임으로 등록합니다. 검증용 공개 업무계획에는 11월 27일에 아직 배포되지 않은 ‘공개 업무 연결 자료’ 항목이 필요합니다. 이 항목의 ID는 기본값 `task-browser-source`를 사용하거나 JSON의 `sourceId`로 지정합니다.
